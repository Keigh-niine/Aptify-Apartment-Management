# Aptify

Apartment management for landlords and tenants in the Philippines. Landlords manage
properties, units, invites, maintenance requests, announcements, and the rent ledger. Tenants
pay bills (GCash, Maya, or cash), download receipts, and submit repair requests.

Built with [Next.js](https://nextjs.org) (App Router, Cache Components), React, Tailwind CSS,
and [Supabase](https://supabase.com) (Postgres, Auth, Storage).

## Prerequisites

- Node.js 20 or newer
- A Supabase project
- (Optional) A Google AI Studio API key for AI maintenance descriptions

## Setup

### 1. Install dependencies

```bash
npm install
```

### 2. Set up Supabase

In the Supabase dashboard, open **SQL Editor** and run these files in order:

1. `schema.sql`: the full schema (tables, views, functions, RLS policies, storage buckets).
   Run it **once** on a fresh project. Do not run it on a database that already has these tables.
2. `hardening.sql`: tightens function permissions and receipt storage rules. Run it once,
   ideally on a staging copy first, then re-test login, signup with an invite code, paying a bill,
   and confirming a payment.

Monthly bills are generated by `generate_all_monthly_bills()`. To run it automatically, enable the
`pg_cron` extension and uncomment the `cron.schedule` line near the end of `schema.sql`.

### 3. Configure environment variables

Copy `.env.example` to `.env.local` and fill in the values:

```bash
cp .env.example .env.local
```

| Variable | Required | Notes |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Supabase > Project Settings > API |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Yes | Same page. Safe to expose to the browser. |
| `GEMINI_API_KEY` | No | Server-only. Never prefix with `NEXT_PUBLIC_`. Without it, the AI description button returns a 503. |
| `GEMINI_MODEL` | No | Defaults to `gemini-2.5-flash`. |

Restart the dev server after changing environment variables.

### 4. Run it

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Project structure

```
src/
  app/            Routes: /login, /signup, /dashboard, /landlord/*, /tenant/*, /api/*
  components/     UI, grouped by area (auth, landlord, tenant, settings, ui)
  lib/            Data access and helpers (Supabase clients, ledger, units, payments, time, ...)
  proxy.ts        Redirects signed-out visitors away from /dashboard, /landlord, /tenant
schema.sql        Full database schema
hardening.sql     Security patch for permissions and storage policies
```

Access control lives in two places: `src/proxy.ts` redirects signed-out users, and Supabase
row-level security enforces what each signed-in user can read and write.

## AI maintenance descriptions

Tenant maintenance requests can use Google Gemini to draft a description from the request
title, category, and urgency. Create an API key in Google AI Studio and set `GEMINI_API_KEY`
(see the table above). Tenants can review and edit the generated description before submitting.

The route (`/api/tenant/maintenance/description`) requires a signed-in tenant with an active
lease and limits each user to 10 requests per 10 minutes. The limiter is in memory, so on
serverless hosting each instance counts separately. For a strict cap, move it to the database
or a shared store such as Upstash Redis.

## Deployment

Deploy to [Vercel](https://vercel.com/new) or any host that supports Next.js. Set the same
environment variables in the host's settings, then run `npm run build`.
